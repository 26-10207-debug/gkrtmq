# 검색·원본 보기 업데이트 검증

## 구조

공개 사이트 검색, 공개 REST 검색과 MCP 검색은 `lib/search-service.ts`를 사용한다. 원본 저장과 PC의 본문 추출을 분리하고, 서버에는 위치가 있는 작은 본문 구간과 FTS 색인을 저장한다. 이전 검색은 한 릴리스 동안 남겨 두며, 관리자 PC 처리기의 `activate` / `rollback`으로 전환한다. 새 스키마 배포만으로는 검색을 전환하지 않는다.

PC 처리기는 `scripts/indexer/README.md`를 따른다. 기본은 수동 실행이다. PC가 꺼져 있어도 저장된 검색 색인·원본 열람은 서버에서 제공한다. 현재 외부 출처는 이용 조건을 확인한 범위에서 제목·설명·원문 링크를 저장하며 원본 파일을 재배포하지 않는다.

## 로컬 확인

- TypeScript 검사와 배포 빌드 통과.
- 실제 SQLite FTS 시험 10,136건: 정확한 제목 순위, 반복 단어와 긴 제목, 한국어 2글자·초성·띄어쓰기·동의어, 여러 페이지의 AND 검색, 필터, 60개 초과 페이지 이동, 10만 자 이후 본문, 코드 검색, 비공개 제외, 커서 일관성 통과.
- 이전 작업 임대와 최신 자료 버전이 다른 경우 쓰기가 원자적으로 거부되는지 확인. 구간을 짧게 재처리할 때 오래된 꼬리 조각 삭제 확인.
- DOCX의 숫자·XML 엔터티, 긴 코드, HTML 스크립트 제외, ZIP 경로 제한, 이미지 미리보기, PDF 2쪽과 마지막 쪽 추출 통과.
- 한국어·영어 Tesseract 모델을 실제 로드해 영문 이미지 OCR 시험 통과. 모든 한국어 스캔·필기·수식의 정확도를 보증하는 결과는 아니다.
- 원본 파일 응답 HEAD, 단일 Range, 206/416, ETag 304, If-Range 불일치 전체 응답 통과.
- 데스크톱 브라우저의 360·390·430px 및 가로 화면에서 전체 맞춤, 이미지 확대, PDF 마지막 쪽, 고정 게임 맞춤·내부 터치·전체 화면 재클릭 해제 확인.

## 실제 자료 평가 (2026-09-08)

보호된 새 검색으로 실제 공개 자료 465건을 평가했다. 사용자 원본 335개(304 PDF, 28 JPEG, 2 ZIP, 1 text/plain), 폴더·기본 자료·외부 참고 자료를 포함한다. 기존 본문을 먼저 별도 색인에 옮겼으며, 원본 전부를 새 추출기로 읽었다는 의미는 아니다.

- 검색 실행 전에 기대 자료를 저장한 100개 평가: 유일 제목 60개 모두 1위, 실제 본문 문구 40개 모두 상위 10위. 합계 100/100 통과. 이 자동 생성 평가만으로 모든 한국어 질의 품질을 보증하지 않는다.
- 생산 서버 내부 처리 p95 209ms, 이 PC까지 전체 응답 p95 421ms, 응답 크기 p95 5,331 bytes, 검색 관련 읽은 행 p95 3,330.
- 단어 게임 ZIP 2개는 새 처리기 2.0.1로 내부 본문 전체 추출 완료. 나머지 원본 333개는 신규 추출 완료 전이며, 기존 10만 자 제한에 걸린 원본 2개도 다시 읽어야 한다.
- 외부 출처 7개를 확인했다. 허용된 범위만 접근하며 현재 제목·설명·원문 링크만 검색한다. 확인 시도 수는 EBSi 1, 경기 55, 인천 1, 평가원 2, OpenStax 1, PhET 2, 서울 1이며 모두 본문 수집 성공을 의미하지 않는다.
- 새 검색을 활성화한 격리된 로컬 환경에서 웹·공개 API·MCP 5개 질의의 자료 및 순위 일치. 생산 MCP의 새 엔진 전환 후 비교는 아직 남아 있다.

## 1만 건 부하 시험

서로 다른 파일 해시를 포함한 10,136개 문서, SQLite 색인 19,763,200 bytes로 시험했다. 로컬 Wrangler D1, 일반 데스크톱 CPU 조건이며 생산 D1의 1만 건 실측 또는 모바일 네트워크 시험이 아니다.

| 조건 | 내부 처리 시간 | 읽은 행 수 |
|---|---|---|
| 캐시가 없는 서로 다른 질의 5개 | 162, 188, 244, 336, 497ms | 70,969~201,005 |
| 위 질의를 반복한 50개 요청 | p50 46ms, p95 64ms | p95 20,376 |

반복 50회 모두 캐시에 적중했다. 캐시는 30초, 최대 40개·직렬화된 UTF-8 약 1MB이며 개인 권한 응답을 저장하지 않는다. 매번 공개 여부·색인 버전·자료 메타데이터·실제 일치 구간·본문 처리 상태를 확인하고 과목 목록을 다시 계산한다. 폴더 결과는 캐시하지 않는다. 비공개 전환, 본문 및 위치 변경, 미리보기 교체, 조회수 변경, 이전 커서, 실패 후 재생성의 읽은 행 수를 검증했다.

캐시 없는 넓은 검색 2개는 300ms 목표를 넘었다. 최초·반복 검색을 섞어 목표 달성으로 표시하지 않는다. 초기 캐시 없는 검색의 추가 최적화와 생산 규모 시험이 남아 있다.

## 전환 상태와 남은 출시 조건

새 검색은 코드와 별도 색인까지 배포했고 **공개 검색의 v2 전환은 보류**한다. 기존 검색 및 색인은 유지한다. 모바일 원본 뷰어와 파일 Range/HEAD 응답 개선은 적용된다.

남은 조건은 원본 333개의 전체 재처리, 제한 뒤쪽 내용의 실제 원본 확인, 처음 하는 넓은 검색 성능 개선, 생산 MCP 순위 일치 확인, iOS Safari·Android Chrome 실기기 및 10Mbps/RTT 150ms/CPU 4배 감속 환경 확인이다. Core Web Vitals 현장 p75도 아직 측정하지 않았다. 화면 크기 시험 통과를 실기기 통과로 표시하지 않는다.

재처리 시 본문은 임시 구간에 저장하고 완료 시 원자적으로 교체한다. 중단·실패·빈 OCR 결과는 기존 본문을 삭제하지 않는다. 구버전 처리기 및 만료 임대의 쓰기를 거부한다. 실패·미지원·일부 완료 상태와 원본 다운로드를 유지한다.

유료 서비스로 자동 전환하지 않는다. 인증값·자료 본문·평가 질의·OCR 모델은 Git에서 제외한 `.indexer/`에만 보관한다.
